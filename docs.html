接口文档（API）

代码方块把你写的 Java 程序当作一个「每 tick 跑一次的小芯片」。程序实现 CodeBlockProgram 接口的 onTick(CodeContext ctx, long tick)， 模组在合适时机调用它，并传入 ctx——所有跟 MC 世界打交道的能力都挂在这个上下文对象上。

最小可运行程序

import codeblockmod.api.CodeBlockProgram;
import codeblockmod.api.CodeContext;

// 文件名必须与类名一致：CB_block1.java
public class CB_block1 implements CodeBlockProgram {
    public void onTick(CodeContext ctx, long tick) {
        int v = ctx.readInput(4);      // 读西面(4)的红石强度
        ctx.writeOutput(5, v);       // 原样写到东面(5)
    }
}
约束：文件名、类名、方块名字三者必须一致。方块名为 block1 时， Java 文件就是 CB_block1.java，类名必须是 CB_block1。 这是 Java「public 类名 = 文件名」的硬要求，不是模组的限制。
运行模型与线程安全
什么时候跑？在哪条线程跑？能写死循环吗？

只有两种时机会跑程序

  • ① 手动运行：首次载入方块、准星对着方块按 O、右键方块重载。
  • ② 检测到更改运行：程序文件 mtime 变化（每 20 tick 扫一次），或邻居红石变化（去抖 4 tick 后跑一次）。
模组绝不会每 tick 偷偷轮询跑你的程序。 没写循环 = 一次事件跑一次；写了 while (true) 就由你自己的代码一直循环。

线程模型

你的 onTick 跑在后台守护线程里，不阻塞服务端主线程。 ctx 里凡是触碰世界的操作（读红石、写输出、发消息、放音）都会自动经 runOnMain() 调度回服务端主线程执行，所以你不需要自己加锁或调度， 直接在 onTick 里调用即可。

速度上限（MC 引擎天花板）

服务端 20 TPS，1 tick = 50ms 就是最快速度。红石灯/红石线最快约 20Hz， 「隔 1ms 闪一次」物理上做不到。sleepTicks(1) 已经是最短等待。

看门狗

按设计，任何循环都永不自动终止。只有当程序连续 10 秒从未让出 CPU （循环体内缺少「等待」的纯空转）时，才会在日志里打一条 WARN 提示——不会中断线程、不会清输出。 自己用 sleepTicks() / sleep() 让出 CPU 即可规避占满单核。

红石 I/O（cin / cout）
强度 0–15，即十六进制 0–F

2北 NORTH—Z 方向
3南 SOUTH+Z 方向
4西 WEST—X 方向

接口一览

方法说明
int readInput(int channel)读某面外部输入的红石强度（0–15）。已排除本方块自身在该面发出的信号，避免自激。
void writeOutput(int channel, int value)向某面输出强度，自动 clamp 到 0–15。
int readInputMax()返回 6 个面中最大的输入强度。
void writeOutputAll(int value)6 个面同时输出相同强度（自动 clamp）。
String debugInputs()返回 6 个方向当前输入的可读字符串。接线不确定时用它确认拉杆/压力板到底接在哪一面。已实现
接线铁律：输入端与输出端物理分离。 例如「读西面、写东面」。若把输出和读取接到同一段红石粉，自己的信号会反馈回来被自己读到（物理自激）， 表现就是 0/1 反复跳。readInput 只排除本方块自身发射量，排除不了同一段红石线的反射。

例：阈值比较器

public void onTick(CodeContext ctx, long tick) {
    int v = ctx.readInput(4);              // 读西面
    ctx.writeOutput(5, v >= 8 ? 15 : 0);   // 东面：够强就满输出
}
跨 tick 状态与等待
计数器、计时器、延时
方法说明
int getStateInt(String key)读取跨 tick 持久化的整数状态（计数器/计时器/标志位）。key 不存在返回 0。
void setState(String key, int value)写入整数状态。每个代码方块有自己独立的状态表。
void sleepTicks(long n)真阻塞 n 个游戏 tick（1 tick ≈ 50ms），期间让出 CPU。用于延时/降频。
void sleep(long millis)真阻塞指定毫秒。在 while(true) 里用它让出 CPU 降频。

例：每 20 tick 计一次数

public void onTick(CodeContext ctx, long tick) {
    int n = ctx.getStateInt("count");
    ctx.setState("count", n + 1);
    ctx.writeOutput(5, n % 16);   // 0–F 循环输出
    ctx.sleepTicks(20);              // 约 1 秒一次，同时让出 CPU
}
死循环务必带等待。while(true) 里如果没有 sleepTicks() 或 sleep()，会纯空转占满一个 CPU 核心（看门狗只会打日志，不会帮你停）。
消息、音效与屏幕提示
跟玩家沟通
方法说明
void sendMessage(String text)聊天框发一条消息，方圆 64 格内玩家可见。支持 § 颜色码。同文本 1 秒内去重。
void sendClickable(String text, String url)可点击消息（悬停下划线）。以 http 开头＝打开链接，否则当作 MC 命令执行。3 秒去重。
void playSound(String soundId)播放原版音效，方圆 16 格可听到。例：block.note_block.harp、entity.player.levelup。ID 无效时回退竖琴音。
void sendActionBar(String text)物品栏上方短暂文字（Action Bar），约 3 秒消失。
void sendTitle(String text)屏幕中央大标题。

例：可点击链接

ctx.sendClickable("§b点我打开文档", "https://codeblock.cc.cd/docs.html");
ctx.sendClickable("§a点我回到出生点", "/spawn");
自定义音频
播放你自己的 mp3 / wav / ogg

音频文件放在存档目录的 res/media/ 下，用文件名直接播放（流式 SourceDataLine，mp3 已内置解码）。

方法说明
void playAudio(String filename, float volume)播放 res/media/ 下的音频。调一次播一次，次数完全由你的代码决定。音量 >1 视为百分比（100=满音量），否则按 0.0–1.0。
void stopAudio()停止该方块正在播放的所有自定义音频。
void stopAudio(String filename)停止指定文件名的音频。
 
ctx.playAudio("ding.mp3", 80);   // 80% 音量
// ...
ctx.stopAudio("ding.mp3");        // 只停这一首
并发上限为每方块 8 条音频线路（防止资源耗尽），超出的播放请求会被丢弃。文件不存在时会回退一声竖琴提示音。

路径 / 文件用途

命名规则已实现

  • 方块名 block1 → 代码文件固定为 CB_block1.java，名字与代码绑定。
  • 名字只允许字母 / 数字 / 下划线 / 中文；禁止为空、禁止与别的方块重名。
  • 改名会同步重命名整套 CB_<旧名>.* 文件，并自动改写 .java 里的类名、删除陈旧 .class（下次编译重建）。
改名界面已改为游戏内（右 Shift + 右键代码方块，弹出游戏内 Screen，支持中文输入法）， 不再使用浏览器弹窗。

编辑器里的快捷操作已实现

  • 📄 用默认应用打开 Java 代码：用系统默认程序打开当前方块的 CB_<名字>.java。
  • 📂 打开代码文件夹：在文件管理器打开 res/program/。
