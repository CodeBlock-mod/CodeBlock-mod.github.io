接口文档（API）

代码方块把你写的 Java 程序当作一个「每 tick 跑一次的小芯片」。程序实现 CodeBlockProgram 接口的 onTick(CodeContext ctx, long tick)， 模组在合适时机调用它，并传入 ctx——所有跟 MC 世界打交道的能力都挂在这个上下文对象上。

最小可运行程序

import codeblockmod.api.CodeBlockProgram;
import codeblockmod.api.CodeContext;

// 文件名必须与类名一致：CB_block1.java
public class CB_block1 implements CodeBlockProgram {
    public void onTick(CodeContext ctx, long tick) {
        int v = ctx.readInput(4);      // 读西面(4)的红石强度
        ctx.writeOutput(5, v);       // 原样写到东面(5)
    }
}
约束：文件名、类名、方块名字三者必须一致。方块名为 block1 时， Java 文件就是 CB_block1.java，类名必须是 CB_block1。 这是 Java「public 类名 = 文件名」的硬要求，不是模组的限制。
运行模型与线程安全
什么时候跑？在哪条线程跑？能写死循环吗？

只有两种时机会跑程序

  • ① 手动运行：首次载入方块、准星对着方块按 O、右键方块重载。
  • ② 检测到更改运行：程序文件 mtime 变化（每 20 tick 扫一次），或邻居红石变化（去抖 4 tick 后跑一次）。
模组绝不会每 tick 偷偷轮询跑你的程序。 没写循环 = 一次事件跑一次；写了 while (true) 就由你自己的代码一直循环。

线程模型

你的 onTick 跑在后台守护线程里，不阻塞服务端主线程。 ctx 里凡是触碰世界的操作（读红石、写输出、发消息、放音）都会自动经 runOnMain() 调度回服务端主线程执行，所以你不需要自己加锁或调度， 直接在 onTick 里调用即可。

速度上限（MC 引擎天花板）

服务端 20 TPS，1 tick = 50ms 就是最快速度。红石灯/红石线最快约 20Hz， 「隔 1ms 闪一次」物理上做不到。sleepTicks(1) 已经是最短等待。

看门狗

按设计，任何循环都永不自动终止。只有当程序连续 10 秒从未让出 CPU （循环体内缺少「等待」的纯空转）时，才会在日志里打一条 WARN 提示——不会中断线程、不会清输出。 自己用 sleepTicks() / sleep() 让出 CPU 即可规避占满单核。

接口一览

方法说明
int readInput(int channel)读某面外部输入的红石强度（0–15）。已排除本方块自身在该面发出的信号，避免自激。
void writeOutput(int channel, int value)向某面输出强度，自动 clamp 到 0–15。
int readInputMax()返回 6 个面中最大的输入强度。
void writeOutputAll(int value)6 个面同时输出相同强度（自动 clamp）。
String debugInputs()返回 6 个方向当前输入的可读字符串。接线不确定时用它确认拉杆/压力板到底接在哪一面。已实现
接线铁律：输入端与输出端物理分离。 例如「读西面、写东面」。若把输出和读取接到同一段红石粉，自己的信号会反馈回来被自己读到（物理自激）， 表现就是 0/1 反复跳。readInput 只排除本方块自身发射量，排除不了同一段红石线的反射。

例：阈值比较器

public void onTick(CodeContext ctx, long tick) {
    int v = ctx.readInput(4);              // 读西面
    ctx.writeOutput(5, v >= 8 ? 15 : 0);   // 东面：够强就满输出
}
跨 tick 状态与等待
计数器、计时器、延时
方法说明
int getStateInt(String key)读取跨 tick 持久化的整数状态（计数器/计时器/标志位）。key 不存在返回 0。
void setState(String key, int value)写入整数状态。每个代码方块有自己独立的状态表。
void sleepTicks(long n)真阻塞 n 个游戏 tick（1 tick ≈ 50ms），期间让出 CPU。用于延时/降频。
void sleep(long millis)真阻塞指定毫秒。在 while(true) 里用它让出 CPU 降频。

例：每 20 tick 计一次数

public void onTick(CodeContext ctx, long tick) {
    int n = ctx.getStateInt("count");
    ctx.setState("count", n + 1);
    ctx.writeOutput(5, n % 16);   // 0–F 循环输出
    ctx.sleepTicks(20);              // 约 1 秒一次，同时让出 CPU
}
死循环务必带等待。while(true) 里如果没有 sleepTicks() 或 sleep()，会纯空转占满一个 CPU 核心（看门狗只会打日志，不会帮你停）。

命名规则已实现

  • 方块名 block1 → 代码文件固定为 CB_block1.java，名字与代码绑定。
  • 名字只允许字母 / 数字 / 下划线 / 中文；禁止为空、禁止与别的方块重名。
  • 改名会同步重命名整套 CB_<旧名>.* 文件，并自动改写 .java 里的类名、删除陈旧 .class（下次编译重建）。
改名界面已改为游戏内（右 Shift + 右键代码方块，弹出游戏内 Screen，支持中文输入法）， 不再使用浏览器弹窗。

编辑器里的快捷操作已实现

  • 📄 用默认应用打开 Java 代码：用系统默认程序打开当前方块的 CB_<名字>.java。
  • 📂 打开代码文件夹：在文件管理器打开 res/program/。
进阶 API
代码 API 与编辑器积木完整参考

本页分两部分：① 代码 API（直接写 Java 用的方法清单）、② 编辑器积木（图形化拖拽对应的积木清单）。两者一一对应。

一、代码 API（Java 方法）

字符串数组（一维）已实现

怎么创建名单？不用显式创建。直接用 arrayAdd("名单名", "值") 调用，模组发现这个"名单名"还不存在就自动建一个空数组。每个方块各自独立，跨 tick 持久化（存档退出再进还在）。key 支持中文。

方法用途
void arrayAdd(key, v)往名单末尾加一个值，允许重复。
void arrayAddOnce(key, v)只在名单里没有这个值时才加（去重），最常用于"白名单/已领奖名单"。
void arrayRemove(key, v)从名单里删掉第一个匹配的值。
void arrayClear(key)清空整个名单。
int arraySize(key)名单里有几个元素。
String arrayGet(key, i)取第 i 个元素（从 0 开始数），越界返回空字符串。
int arrayFind(key, v)找这个值在第几位（0 起），找不到返回 -1。判断"在不在名单里"就用 arrayFind(...) >= 0。
String arrayJoin(key, sep)把名单所有元素用分隔符拼成一个字符串，方便 sendMessage 打印。
void setString(key, v) / String getString(key)存/取单个字符串状态（不是数组，就是一个 key→一个字符串）。
替代记分板：判断"某玩家是否属于某组"（白名单/黑名单/已领奖），不要用记分板，直接 arrayFind("vip", playerName) >= 0 一行搞定，无需建 objective。

二维字符串数组（表格）已实现

行 × 列的表格，存成绩表 / 配置矩阵。同样用 key 自动创建。编辑器里「创建二维数组」积木直接填行数和列数，下面自动长方格。

方法用途
void array2DSet(key, r, c, v)写第 r 行第 c 列（都从 0 起），行/列不够自动补空行。
String array2DGet(key, r, c)读第 r 行第 c 列，越界返回空字符串。
int array2DRows(key) / int array2DCols(key)表格有几行 / 几列。
int array2DFind(key, v)全表找这个值在第几行，找不到 -1。
String array2DRowJoin(key, r, sep)把某一行用分隔符拼成字符串。
void array2DClear(key)清空整张表。

红石输入/输出已实现

方法用途
int readInput(channel)读某一面接收到的红石强度（0-15）。channel：0=下 1=上 2=北 3=南 4=西 5=东。
int readInputMax()6 个面里最大的红石强度。
void writeOutput(channel, v)往某一面输出红石强度（自动 clamp 0-15）。

精确识别"是谁按的按钮"已实现

监听玩家右键交互，不靠"谁离得近"猜——多人围在一起时，只有真正按下去的人会被记到。

方法用途

命令执行（最高权限）已实现

所有命令都在最高权限下跑——服务器关了命令、玩家不是 OP 也能执行。位置默认在方块中心。

方法用途
void executeCommand(cmd)执行一条命令。/execute 的各种子命令（if/as/at/store 等）直接写在 cmd 字符串里即可，无需专门 API。
void executeCommandAs(player, cmd)以指定玩家身份执行，命令里的 @s 指向他，仍最高权限。
int executeCommandResult(cmd)执行并拿到返回值：0=失败/条件不成立，1=成功，其他=命令本身的返回值（如 /list 人数、data get 取到的数）。
boolean executeCommandTest(cmd)等价于 executeCommandResult(cmd) > 0，专门给 /execute if 条件判断用，放进 if 更顺手。
int executeCommandResultAs(player, cmd)以玩家身份执行并取返回值。
/execute if 不成立 ≠ 返回 0。MC 底层条件不成立会抛异常，模组已统一捕获并归一为 0，你直接判断返回值就行，不用 try-catch。

记分板读写已实现

需要存数值（如金币数、击杀数）时用。目标不存在时自动创建 dummy 目标，开箱即用。纯判断"在不在组里"用字符串数组更简单，不必用记分板。

方法用途
int getScore(objective, player)读某玩家在某记分板目标上的分数，查不到返回 0。
void setScore(objective, player, v)直接设分数。
void addScore(objective, player, delta)加/减分数（负数即减）。

// 西面按钮按下时
if (ctx.inputChanged(4) && ctx.readInput(4) > 0) {
    String p = ctx.whoUsed(-1, 0, 0);          // 是谁按的
    if (!p.isEmpty()) {
        if (ctx.arrayFind("vip", p) >= 0) {              // 在 VIP 名单里？
            ctx.executeCommand("give " + p + " diamond 1");  // 发钻石
        } else {
            ctx.arrayAddOnce("vip", p);                   // 不在就加入名单
        }
    }
}
典型链路：inputChanged 边沿检测 → whoUsed 精确识别 → arrayFind 名单判断 → executeCommand 执行命令。全程无需记分板。
execute 命令详解
/execute 子命令语法、用途与示例

/execute 是 MC 最强大的命令——改执行者、改位置、加条件、存结果，一条命令全搞定。代码方块里所有 execute 积木最终都是拼出 execute ... run ... 字符串交给 ctx.executeCommand() 执行。

基本结构

execute [修饰子命令] [条件子命令] [store子命令] run <要执行的命令>

子命令从左到右依次生效，run 只能放最后。除 run 外，其他子命令可多个串联、可重复。

一、修饰子命令（改「在哪跑、以谁的身份跑」）

子命令用途 + 示例
as <选择器> 改执行者（命令里的 @s 指向它），不改位置。
例：execute as @a run say 你好 → 每个玩家都说"你好"。
at <选择器> 改执行位置/朝向/维度，不改执行者。
例：execute at @p run setblock ~ ~ ~ stone → 在最近玩家脚下放石头。
as <选择器> at @s 执行者+位置一起改（最常用）。
例：execute as @a at @s run particle flame ~ ~1 ~ → 每个玩家头上冒火焰粒子。
positioned <x> <y> <z> 指定绝对/相对坐标。~ = 相对当前位置，^ = 相对朝向。
例：execute positioned ~ ~1 ~ run setblock ~ ~ ~ diamond_block → 头顶放钻石块。
in <维度> 切换执行维度：minecraft:overworld / the_nether / the_end。

二、条件子命令（if 成立 / unless 不成立才继续）

子命令用途 + 示例
if/unless entity <选择器> 实体存在/不存在。
例：execute if entity @e[type=zombie,r=10] run say 附近有僵尸！
if/unless block <x y z> <方块> 某位置是不是指定方块。
例：execute if block ~ ~-1 ~ minecraft:gold_block run say 脚下是金块！
if/unless blocks <x1 y1 z1> <x2 y2 z2> <x y z> all|masked 两个区域方块是否一致。all=全比，masked=只比非空气。
if/unless items entity <选择器> <槽位> <物品> 实体某槽位是否有某物品。槽位如 weapon.mainhand、armor.head、hotbar.0。
例：execute if items entity @s weapon.mainhand minecraft:diamond run say 手持钻石！
if/unless predicate <谓词> 数据包谓词条件（高级，用于复杂判定）。
if/unless score <目标> <记分项> <操作符> <值> 记分板分数比较。操作符：= > >= < <=，或 matches 范围。
例：execute if score @s money matches 100.. run say 我有100块以上！
纯判断"玩家在不在名单里"不要用 score。用字符串数组的 arrayFind(key, 玩家名) >= 0 更简单，无需建记分板目标。

三、存储子命令（把命令结果存下来）

子命令用途 + 示例
store result score <玩家> <记分项> run <命令> 把 run 后命令的返回值存进记分板。
例：execute store result score @s online run list → 把在线人数存进 @s 的 online 分数。
store success score <玩家> <记分项> 存命令是否成功（0/1）。
返回值语义：0 = 失败/条件不成立，1 = 成功，其他 = 命令本身返回的数。 在代码方块里可以用 ctx.executeCommandResult("execute ... run ...") 直接拿到这个返回值，不用 store 到记分板。

四、常用组合示例

// 1. 让所有玩家传送到代码方块位置
ctx.executeCommand("execute as @a at @s run tp ~ ~ ~");

// 2. 头顶是钻石块就给最近玩家发钻石
if (ctx.executeCommandTest("execute if block ~ ~1 ~ minecraft:diamond_block")) {
    ctx.executeCommand("give @p diamond 1");
}

// 3. 统计半径 5 格内的僵尸数量，存进记分板
int zombieCount = ctx.executeCommandResult(
    "execute if entity @e[type=zombie,distance=..5]");
ctx.sendMessage("附近僵尸数: " + zombieCount);

// 4. 对 VIP 名单里的每个玩家发奖励（用字符串数组，不用记分板）
for (int i = 0; i < ctx.arraySize("vip"); i++) {
    String p = ctx.arrayGet("vip", i);
    ctx.executeCommand("give " + p + " diamond 1");
}

// 5. 手持钻石剑才执行后续命令
ctx.executeCommand("execute if items entity @s weapon.mainhand minecraft:diamond_sword run effect give @s strength 10 1");
在编辑器里：以上都有对应积木，直接在 [Exec] 执行/判断命令 分类里拖，不用手敲命令字符串。带返回值的用「命令成立?」「取结果」积木。
